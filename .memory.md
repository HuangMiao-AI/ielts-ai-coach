# IELTS AI Coach Project Memory

Last updated: 2026-07-19

## Current State

IELTS AI Coach is a local Streamlit modular monolith using Python 3.12,
SQLAlchemy, SQLite, Argon2id, Pydantic, and pytest. Authentication, profiles,
deterministic diagnosis and planning, tasks, study logs, AI coaching, Level 2
writing feedback, dashboard/history, and user-owned data controls are active.

V2.1 Phase 1 adds the first complete Academic reading-practice loop:

```text
today task
→ start or continue
→ answer every question
→ submit once
→ deterministic score and review
→ persisted attempt history
→ synchronized task completion and study log
```

The pre-exporter automated baseline was 74 passing tests. The current premium
UI/PWA branch baseline is 160 passing tests, including 54 unchanged exporter
tests. Python 3.12.13, Streamlit 1.59.2, and the installed dependency set have
been verified locally.

AI Learning Analytics V1 Task 1 is complete on
`feature/ai-learning-analytics-v1` in commit `291274d`. It adds the
read-only, user-scoped `services/analytics.py` contract and aggregation service
plus `list_user_writing_feedback`. Analytics returns frozen DTOs for score
trends, weighted Reading evidence, Writing-dimension trends, and 90-day study
behavior without schema or data writes. Malformed Reading snapshots retain
stored score totals and yield only the safe `invalid_reading_snapshot` warning.

## Database

Local development uses SQLite through a configurable `DATABASE_URL`. Schema
initialization uses additive SQLAlchemy `create_all`; old tables and fields are
not removed or rewritten.

The active model set contains 11 tables:

- `users`
- `student_profiles`
- `score_records`
- `study_plans`
- `plan_tasks`
- `study_logs`
- `coach_messages`
- `ai_usage_daily`
- `essays`
- `writing_feedback`
- `task_question_attempts`

All user-owned business records are scoped by authenticated `user_id`.
Documentation must not record real user data or production row counts.
Databases, WAL/SHM files, backups, and test runtime data are excluded from Git.

## Reading Practice Decisions

- The two banks contain eight project-original Academic passages and 77
  questions: v1 has three 9-question passages and v2 has five 10-question
  passages.
- Supported types are Multiple Choice, True/False/Not Given, and Matching
  Heading.
- Every question has options, a correct answer, an explanation, and evidence.
- Answers are normalized for Unicode, repeated whitespace, and case before
  deterministic comparison.
- Correct answers, explanations, and evidence are hidden before final
  submission.
- One final submission is allowed per task. A duplicate submission returns the
  original result and cannot overwrite history.
- The persisted attempt stores passage/version identity, submitted answers,
  score, total, accuracy, wrong-question IDs, a complete review snapshot, and
  completion time.
- Submission, task completion, and study-log synchronization occur in one
  transaction.
- Submitted reading completion cannot be independently cancelled because that
  would make attempt history and study logs inconsistent.
- Reading deletion follows the existing user-owned learning-data deletion
  boundary.
- The dedicated Reading route provides instructions, a stable timer,
  article/question modes, one-question navigation, submission confirmation,
  deterministic results, and locked history review.
- Unfinished Reading drafts are intentionally session-only.

All bundled passages, questions, explanations, and evidence are original
IELTS-style practice, not official IELTS or Cambridge test content.

## UI, Skill Flows, and PWA Decisions

- A single route registry drives the desktop sidebar and the 56-pixel mobile
  bottom navigation. Scores, Today, Coach, and Settings remain contextual
  routes rather than duplicate primary navigation.
- The shared design system uses safe-area spacing, reduced-motion handling,
  responsive glass surfaces, and 44-pixel minimum primary exam controls.
- Home aggregates only current-user records for streak, latest Reading and
  Writing results, weak sections, current plan, activity, and a deterministic
  recommended route.
- Listening is an explicitly labeled Demo using student-owned material. It
  persists and claims no score.
- Writing has live word count, user/task-scoped session drafts, stable edit
  time, clear/submit confirmation, and duplicate-click protection while
  retaining the existing provider, quota, feedback, and history boundaries.
- Speaking supports Part 1/2/3 prompts, preparation and response timers,
  notes, and browser-session recording. Audio is not uploaded and no automatic
  score is provided.
- PWA support consists of a manifest, mobile metadata, and deterministic local
  icons. No service worker is registered and offline availability is not
  claimed.

## AI Decisions

- Core scores, plans, tasks, reading answers, and quotas use deterministic
  Python rules.
- AI is limited to natural-language coaching and writing feedback.
- No configured API key selects local Mock mode.
- Qwen-compatible HTTP calls remain behind the provider interface.
- Tests use Mock or fake providers and never call a real AI service.
- AI writing scores are educational estimates and are not equivalent to
  official examiner scores.
- Provider errors expose safe messages without credentials or raw response
  bodies.

## Obsidian Exporter V1

- `ielts_ai_coach/exporting/` is the one-way export boundary from the active
  SQLite database to Miao OS Markdown.
- V1 supports finalized Reading attempts and Writing feedback only.
- Every source query requires one explicit `user_id`; no all-users export
  command exists.
- SQLite access uses URI `mode=ro`, `PRAGMA query_only=ON`, and no checkpoint
  or schema operation.
- Strict Pydantic DTOs and explicit transforms allowlist export fields. Essays,
  prompts, complete answers, passwords, tokens, profiles, conversations, raw
  errors, quotas, and absolute database paths are excluded.
- Output identity is `source_entity + source_record_id`; deterministic filenames
  and content fingerprints prevent duplicate notes.
- Dry-run is the default. `--apply` is required for Markdown, state, and log
  writes.
- Generated Markdown is limited to
  `02 IELTS/AI Feedback/<year>/`. State and logs must remain outside the Vault.
- A previous generated-file hash protects user edits. Modified, deleted, or
  source-key-conflicting notes are reported and never overwritten or recreated
  automatically.
- State is isolated per user and written atomically only after Markdown output
  succeeds.
- The Feishu adapter is an inactive no-network stub that reads no credentials.
- Miao OS stores the V1 field registry, reference template, managed-directory
  README, data contract, and one bounded Dashboard DQL. No real feedback note
  was created during implementation.
- Real read-only validation left the database and WAL bytes unchanged. SQLite
  updated only SHM wal-index/read-mark metadata during read connections; no
  checkpoint or business-data write occurred.

## Security and Privacy

- Passwords are stored only as Argon2id hashes.
- Authentication logic remains in `ielts_ai_coach/auth.py`.
- Session state stores only necessary identity state, never passwords.
- Views derive ownership from the authenticated session and do not accept a
  user-supplied `user_id`.
- Secrets are read only from environment variables or Streamlit Secrets.
- `.env`, private Secrets, databases, backups, logs, uploads, caches, virtual
  environments, and historical enterprise files are ignored by Git.
- Example configuration files contain only empty values or placeholders.
- Existing local screenshots are excluded from Git because browser and desktop
  chrome expose environment metadata. Future portfolio captures must be
  cropped and use fictional data.

## Current Limitations

- SQLite is appropriate only for the current local stage.
- The original reading banks have eight passages and no retry workflow.
- Listening has no bundled original audio-practice loop.
- AI calls are synchronous.
- Writing estimates are not calibrated against official examiners.
- Speaking recordings and all unfinished practice drafts are session-only;
  there is no server-side audio archive or automatic speaking score.
- PWA support does not include a service worker or offline authenticated pages.
- User uploads, account self-deletion, password changes, payments, school
  tenancy, production monitoring, migrations, and cloud deployment are not
  implemented.
- Obsidian export is a manually run CLI workflow; automatic triggers and
  scheduling are not implemented.
- Obsidian export supports Reading and Writing only.
- Any manual change to a generated feedback file causes a safe conflict. V1
  does not merge or automatically recreate deleted output.

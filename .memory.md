# IELTS AI Coach Project Memory

Last updated: 2026-07-17

## Current State

IELTS AI Coach is a local Streamlit modular monolith using Python 3.12,
SQLAlchemy, SQLite, Argon2id, Pydantic, and pytest. Authentication, profiles,
deterministic diagnosis and planning, tasks, study logs, AI coaching, Level 2
writing feedback, dashboard/history, and user-owned data controls are active.

V2.1 Phase 1 adds the first complete Academic reading-practice loop:

```text
today task
→ start or continue
→ answer every question
→ submit once
→ deterministic score and review
→ persisted attempt history
→ synchronized task completion and study log
```

The accepted automated baseline is 74 passing tests. Python 3.12.13,
Streamlit 1.59.2, and the installed dependency set have been verified locally.

## Active Structure

- `app.py` is the thin Streamlit entry point.
- `ielts_ai_coach/views/` contains Simplified Chinese presentation and flow
  control.
- `ielts_ai_coach/services/` contains validation and business rules.
- `ielts_ai_coach/database/` contains SQLAlchemy models and repositories.
- `ielts_ai_coach/ai/` contains the provider boundary, Mock implementation,
  Qwen-compatible implementation, and response schemas.
- `ielts_ai_coach/content/question_banks/reading_v1.json` is the versioned
  original reading bank.
- `tests/` contains all active pytest coverage.
- Root legacy MVP modules remain inactive references and are not approved for
  deletion.
- `archive/enterprise-v0/` is historical, read-only, ignored by Git, and must
  never be imported into the active application.

## Database

Local development uses SQLite through a configurable `DATABASE_URL`. Schema
initialization uses additive SQLAlchemy `create_all`; old tables and fields are
not removed or rewritten.

The active model set contains 11 tables:

- `users`
- `student_profiles`
- `score_records`
- `study_plans`
- `plan_tasks`
- `study_logs`
- `coach_messages`
- `ai_usage_daily`
- `essays`
- `writing_feedback`
- `task_question_attempts`

All user-owned business records are scoped by authenticated `user_id`.
Documentation must not record real user data or production row counts.
Databases, WAL/SHM files, backups, and test runtime data are excluded from Git.

## Reading Practice Decisions

- The first bank has three project-original Academic passages with nine
  questions each.
- Supported types are Multiple Choice, True/False/Not Given, and Matching
  Heading.
- Every question has options, a correct answer, an explanation, and evidence.
- Answers are normalized for Unicode, repeated whitespace, and case before
  deterministic comparison.
- Correct answers, explanations, and evidence are hidden before final
  submission.
- One final submission is allowed per task. A duplicate submission returns the
  original result and cannot overwrite history.
- The persisted attempt stores passage/version identity, submitted answers,
  score, total, accuracy, wrong-question IDs, a complete review snapshot, and
  completion time.
- Submission, task completion, and study-log synchronization occur in one
  transaction.
- Submitted reading completion cannot be independently cancelled because that
  would make attempt history and study logs inconsistent.
- Reading deletion follows the existing user-owned learning-data deletion
  boundary.

All bundled passages, questions, explanations, and evidence are original
IELTS-style practice, not official IELTS or Cambridge test content.

## AI Decisions

- Core scores, plans, tasks, reading answers, and quotas use deterministic
  Python rules.
- AI is limited to natural-language coaching and writing feedback.
- No configured API key selects local Mock mode.
- Qwen-compatible HTTP calls remain behind the provider interface.
- Tests use Mock or fake providers and never call a real AI service.
- AI writing scores are educational estimates and are not equivalent to
  official examiner scores.
- Provider errors expose safe messages without credentials or raw response
  bodies.

## Security and Privacy

- Passwords are stored only as Argon2id hashes.
- Authentication logic remains in `ielts_ai_coach/auth.py`.
- Session state stores only necessary identity state, never passwords.
- Views derive ownership from the authenticated session and do not accept a
  user-supplied `user_id`.
- Secrets are read only from environment variables or Streamlit Secrets.
- `.env`, private Secrets, databases, backups, logs, uploads, caches, virtual
  environments, and historical enterprise files are ignored by Git.
- Example configuration files contain only empty values or placeholders.
- Existing local screenshots are excluded from Git because browser and desktop
  chrome expose environment metadata. Future portfolio captures must be
  cropped and use fictional data.

## Current Limitations

- SQLite is appropriate only for the current local stage.
- The original reading bank has three passages and no retry workflow.
- Listening has no bundled original audio-practice loop.
- AI calls are synchronous.
- Writing estimates are not calibrated against official examiners.
- Speaking audio, user uploads, account self-deletion, password changes,
  payments, school tenancy, production monitoring, migrations, and cloud
  deployment are not implemented.

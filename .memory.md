## Timed exam and audio behavior

- Reading, Writing, and Listening use the shared immutable exam controller for
  running, paused, submit confirmation, timed out, and submitted states.
- Their visible countdown is owned by one packaged Components-v1 client. It
  recalculates from the server deadline and `Date.now()` every second without
  Streamlit reruns or session-state writes, freezes from the paused snapshot,
  corrects on browser visibility changes, clamps at zero, emits one timeout
  event, and removes browser timers and listeners during rerender or teardown.
- The previous embedded timer never started because an empty pause-root class
  produced the invalid selector `.` before interval registration.
- Pausing uses a packaged Components-v1 hard-pause client: it makes the whole
  main exam surface inert, blocks body/panel/touch/keyboard scrolling, hides
  the fallback resume action, and restores scroll positions and state before
  resume. Component DOM identifiers are hashed to remain valid for task names
  containing spaces.
- Writing preserves prompt and content through pause/resume by restoring a
  fresh editor identity from the user-scoped draft value. Mock/no-key mode
  still saves without fabricated IELTS feedback or score.
- Listening uses a packaged Components-v1 HTML5 player rather than `st.audio`.
  It accepts controller commands, reports primitive playback state, freezes
  while paused, stops on submit/timeout, and resumes with a pending seek after
  media metadata is ready so a component remount cannot restart at zero.
